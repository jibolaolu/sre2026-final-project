Application Functionalities
Core services, user-facing features, and AI capabilities

Techbleat Global Bank is a cloud-native banking platform comprising six independent services coordinated through an Istio service mesh. Users authenticate via Keycloak SSO, perform financial operations, and interact with an AI finance assistant backed by large language models.

Core Banking Services
👤
User Service
Python 3.12 · FastAPI
Manages customer accounts, profiles, KYC data, and JWT-protected CRUD endpoints. Validates tokens via PyJWT with RS256 JWKS from Keycloak on every request.

Transaction Service
Java 17 · Spring Boot 3
Processes fund transfers, debit/credit operations, and transaction history queries. Enforces cross-account access denial by extracting userId from the JWT and calling assertOwnership() on every read.

Activity Service
Python 3.12 · FastAPI
Consumes domain events from Kafka to build an immutable audit trail of all account activity. Also exposes a JWT-guarded REST API for querying activity history with ownership checks.

Finance Agent
Python 3.12 · LLM Orchestration
AI-powered finance assistant that routes queries to Anthropic Claude (claude-opus-5-5) or OpenAI GPT-4o. Responses stream via Server-Sent Events. Secured by a dedicated RBAC role (banking-ai-agent) enforced at the API level via require_ai_agent_user().

Frontend
React 18 · Vite · Nginx
Single-page application served by Nginx. Integrates Keycloak JS adapter for OIDC/PKCE silent SSO. All API calls include the Bearer JWT. The chat interface renders streaming AI responses incrementally.

Authentication
Keycloak 24 · OIDC / OAuth 2.0
Centralised identity provider with the banking realm. Issues RS256 JWT access tokens. Supports PKCE for the public SPA client, enforces RBAC roles (user, admin, banking-ai-agent), and provides a JWKS endpoint for each service to validate tokens independently.
OIDC PKCEJWT RS256RBAC RolesJWKS EndpointRealm: banking
Security & Access Control

Every service enforces JWT validation independently at the API boundary. The transaction service additionally calls assertOwnership() to confirm the requesting user owns the requested resource — preventing cross-account access even with a valid token. The Istio AuthorizationPolicy layer adds a second enforcement plane: inter-service traffic is blocked unless it carries a valid mTLS peer identity matching the declared source principal.

02
Infrastructure Components
Purpose, configuration, and dependencies for each platform component
Kubernetes Cluster minikube (local) · AWS EKS (production)
Purpose
Container orchestration layer. Manages pod scheduling, rolling deployments, health probes, and horizontal scaling across all banking services.
Namespaces
banking (all app services) · datadog · istio-system · argocd
Deployment Method
Helm chart at k8s/helm/techbleat-bank/. Values split across values.yaml (base), values-local.yaml (minikube), values-eks.yaml (EKS). Secrets passed via --set at deploy time, never committed.
NetworkPolicy
Default-deny across all namespaces. Per-service allow rules open only the required port/protocol pairs. No pod can reach another unless explicitly permitted.
Istio Service Mesh istio-system namespace · Envoy sidecars
Purpose
Mutual TLS enforcement between every pod pair in the banking namespace. Provides L7 traffic management, circuit breaking, and policy enforcement without code changes to services.
mTLS Mode
STRICT PeerAuthentication applied mesh-wide. All traffic between Envoy sidecars is encrypted and mutually authenticated. Plain-text connections are rejected.
Ingress
Istio IngressGateway handles L7 routing via VirtualService and Gateway CRDs. Traffic enters from cloudflared through NodePort 80/443 and is routed to the appropriate backend service.
Authorization
AuthorizationPolicy CRDs restrict traffic to only declared source principals. Services cannot communicate unless the policy explicitly permits it by ServiceAccount identity.
Cloudflare Zero Trust (Tunnel) banking namespace · 2 replicas
Purpose
Exposes the cluster to the internet without opening any inbound firewall ports. The cluster has no public IP. All traffic from the internet enters via Cloudflare's edge and is forwarded through an outbound-only QUIC tunnel.
Edge Features
WAF (Web Application Firewall), DDoS protection, TLS 1.3 termination, Zero Trust access policies, and rate limiting at the Cloudflare edge — before traffic reaches the cluster.
Token Persistence
Tunnel token stored in K8s Secret cloudflare-tunnel-token in the banking namespace. Survives pod restarts and redeployments. The tunnel itself persists in Cloudflare's dashboard independently of the running pods.
Replicas
2 replicas provide high-availability tunnel connections. Each replica maintains an independent persistent connection to Cloudflare, eliminating a single point of failure at the ingress layer.
Keycloak Identity Provider banking namespace · StatefulSet
Purpose
Centralised authentication and authorisation. Issues RS256-signed JWT access tokens. Services validate tokens offline via JWKS without round-tripping to Keycloak on every request.
Configuration
Realm banking imported at startup from a ConfigMap. Clients: banking-frontend (public, PKCE) and banking-service-client (confidential). Roles: user, admin, banking-ai-agent.
Provisioning
A Helm post-install Job (keycloak-provisioner) creates realms, clients, and default users on first deploy. Realm JSON is stored in a ConfigMap and mounted at /opt/keycloak/data/import.
Port
Exposed on port 8080 (internal). Accessed at keycloak.techbleat-bank.local via Istio VirtualService. The JWKS endpoint at /realms/banking/protocol/openid-connect/certs is called by each service on startup.
PostgreSQL 15 banking namespace · StatefulSet · PersistentVolume
Purpose
Primary relational store for all user profiles, transaction records, and activity logs. Each service connects with its own dedicated database user and schema.
Initialisation
SQL init scripts delivered via ConfigMap and mounted at /docker-entrypoint-initdb.d. Creates per-service schemas and grants on first boot.
Backup Strategy
Daily pg_dump CronJob with 7-day retention. Restoration tested via k8s/scripts/restore-postgres.sh. Documented RPO ≤24h, RTO ≤30min in k8s/docs/rpo-rto.md.
Security
Password stored in K8s Secret, injected via secretKeyRef — never hardcoded. NetworkPolicy restricts connections to only the three application services. TLS available via Istio sidecar mTLS between client and pod.
Redis 7 banking namespace · StatefulSet
Purpose
In-memory data store used for session caching, distributed rate limiting, and short-lived token blacklists. user-service reads cached user profiles to reduce PostgreSQL load.
Use Cases
Session cache · API rate limit counters · JWT revocation list · Finance-agent conversation context cache (configurable TTL)
Access
Password-protected. Connection string injected from K8s Secret. NetworkPolicy restricts to only user-service and finance-agent pods. Exposed on port 6379 inside the cluster only.
Note
Datadog autodiscovery picks up Redis but the auth password is not currently injected into the Datadog check configuration — resulting in a recurring authentication error in the agent logs (tracked for fix).
Apache Kafka banking namespace · StatefulSet · 3 topics
Purpose
Asynchronous event bus decoupling the transaction service (producer) from the activity service (consumer). Ensures the audit log is populated reliably even if the activity service restarts.
Topics
txn.events — transaction lifecycle events
user.events — account create/update events
notifications — email/push trigger events (future)
Producer
transaction-service publishes a TransactionCreated or TransactionCompleted event on every successful fund transfer. Idempotent producer configuration prevents duplicate messages on retry.
Consumer
activity-service consumes txn.events in the activity-consumer-group. Offset commits occur only after the activity record is durably written to PostgreSQL — no data loss on consumer restart.
GitHub Actions CI/CD .github/workflows/ · GHCR images
CI Pipeline
On every push: Python unit tests (pytest) and Java unit tests (Maven) run in parallel, then Docker images are built for all 5 services and pushed to GHCR (ghcr.io/jibolaolu/). Build is blocked if any test job fails.
Image Security
Every pushed image is scanned by Trivy (CRITICAL + HIGH). Findings are uploaded to GitHub Security tab as SARIF. Cosign keyless signing via Sigstore OIDC proves each image was built by the CI pipeline and not tampered with post-build.
SBOM
Syft generates an SPDX JSON Software Bill of Materials for each image and attaches it as a workflow artefact. Enables rapid dependency auditing in the event of a supply-chain vulnerability disclosure.
Secret Scan
Gitleaks runs on every commit (full history scan) via gitleaks-action@v2. Configured by .gitleaks.toml. Blocks merge if any committed secret pattern is detected. Pre-commit hook in .pre-commit-config.yaml catches leaks before push.
ArgoCD GitOps argocd namespace · Port 8088
Purpose
Continuously reconciles cluster state with the Helm chart in the GitHub repository. Any drift (manual kubectl edit, failed rollout) is automatically detected and corrected. Provides a visual diff and rollback UI.
Configuration
Application CR watches k8s/helm/techbleat-bank in the GitHub repo. Auto-sync is enabled with self-heal. Helm values are sourced from values.yaml + values-local.yaml.
Access
UI accessible at http://localhost:8088 via port-forward. Initial admin password generated at install time and stored in the argocd-initial-admin-secret Secret in the argocd namespace.
Rollback
Previous deployment manifests are retained as Git commits. A rollback triggers a sync to an earlier commit SHA. Smoke test checklist documented in k8s/docs/rpo-rto.md.
Datadog Agent & Cluster Agent datadog namespace · DaemonSet · app.datadoghq.eu
Purpose
Full-stack observability: infrastructure metrics, APM traces, log aggregation, and Kubernetes orchestration monitoring. 3/3 node agents Running, 1/1 cluster agent Running.
Log Collection
containerCollectAll: true tails all pod log files from /var/log/pods/. Logs are enriched with pod name, namespace, and service tags before forwarding to the EU region endpoint.
minikube Fix
The node agent requires DD_HOSTNAME set from spec.nodeName fieldRef because minikube does not expose a resolvable FQDN. kubelet.tlsVerify: false is set for the self-signed kubelet cert. liveProcessCollection disabled (requires SYS_PTRACE).
APM / Metrics
OpenTelemetry traces forwarded to Datadog via OTLP exporter. SLO burn-rate alert rules defined in the Helm chart. Kubernetes orchestrator data collected by the cluster agent.
OpenTelemetry Collector banking namespace · Deployment
Purpose
Receives distributed traces from Istio Envoy sidecars and application-level instrumentation via OTLP. Exports to Datadog APM and to a local Jaeger instance for development inspection.
Exporters
OTLP → Datadog APM (EU endpoint) · Jaeger gRPC (local, for development) · Prometheus metrics endpoint scraped by Datadog agent
cert-manager Cluster-wide · ClusterIssuer CRD
Purpose
Automates TLS certificate lifecycle for all Ingress resources. Issues Let's Encrypt certificates in production (EKS). Uses a self-signed ClusterIssuer for local minikube deployments.
SRE Criterion A1
Satisfies the HTTPS requirement. Certificate CR template in k8s/helm/techbleat-bank/templates/tls/cluster-issuer.yaml. HTTP→HTTPS redirect enforced via Istio VirtualService rewrite rule on the Keycloak ingress route.

Areas of Improvement
Prioritised findings across security hardening, production readiness, and reliability

The platform satisfies all A1–A12 SRE criteria. The following improvements are recommended to move from a proof-of-concept deployment to a production-grade, hardened system.

Critical — Production Readiness
Critical
Replace Keycloak start-dev mode with start (production mode)
Keycloak is currently started with start-dev, which disables hostname verification and uses an embedded H2 database. For production, switch to start with KC_HOSTNAME, a PostgreSQL backing store, and a proper TLS keystore. The development mode allows access to the admin console without authentication restrictions.
Effort: Medium
Critical
Harden Keycloak password policy (minimum 3 chars is a dev default)
The banking realm currently enforces a 3-character minimum password — a development convenience. Production policy must enforce at minimum 12 characters, complexity rules (upper, lower, digit, special), and a brute-force detection policy with account lockout after N failed attempts.
Effort: Low
Critical
Complete EKS CI/CD pipeline wiring
The values-eks.yaml file exists and the Helm lint job covers it (continue-on-error: true), but the EKS deployment target in deploy.yml is not yet connected to AWS credentials, ECR, or the EKS kubeconfig. An actual production rollout requires IAM role binding, OIDC federation, and secret rotation strategy for the cluster.
Effort: High
High — Security Hardening
High
Lock finance-agent tool allowlist to per-user scope
The finance-agent enforces the banking-ai-agent role at the API boundary, but the set of tools available to the LLM is not scoped to the authenticated user's own data. A malicious or confused prompt could theoretically instruct the model to query another user's transactions through a tool call. Tool inputs must be validated against the requesting user's JWT claims before execution.
Effort: Medium
High
Inject Redis password into Datadog check configuration
Datadog autodiscovery detects the Redis pod but the check fails with Authentication required because the ad.datadoghq.com/redis.checks pod annotation is not configured with the Redis password reference (%%env_REDIS_PASSWORD%%). This generates recurring errors in the Datadog agent and produces no Redis metrics.
Effort: Low
High
Enable Redis TLS and at-rest encryption
Redis currently uses password auth but plaintext connections within the cluster. Enabling TLS on the Redis port and enabling at-rest encryption for the PersistentVolume would address compliance requirements for session data and JWT revocation lists, which may contain sensitive token identifiers.
Effort: Medium
High
Add Horizontal Pod Autoscaler (HPA) for backend services
Under sustained load (e.g., month-end statement generation, market volatility driving AI chat usage), the transaction service and finance-agent are most likely to become bottlenecks. HPA on CPU/memory with KEDA for Kafka consumer lag would allow automatic scale-out without manual intervention.
Effort: Low
Medium — Reliability & Observability
Medium
Kafka and Redis backup strategy (only PostgreSQL has a backup CronJob)
The daily PostgreSQL backup CronJob and restore script provide RPO ≤24h for relational data. However, the Kafka topic data and Redis session cache have no persistent backup. While Kafka is append-only and Redis is a cache, a stateful restart could lose in-flight events and active sessions. Consider Kafka MirrorMaker for topic replication and Redis AOF persistence.
Effort: Medium
Medium
Propagate distributed trace context (correlation IDs) across all services
The OTEL Collector receives spans from Istio sidecars but application-level trace context (W3C TraceContext headers) is not consistently forwarded by the Python and Java services when making downstream calls. This creates broken trace trees in Datadog APM, making it difficult to correlate a slow user request end-to-end through user-service → transaction-service → Kafka → activity-service.
Effort: Medium
Medium
Increase test coverage — services currently have no test files in CI
The CI pipeline checks for test directories and skips gracefully if none exist. Adding meaningful unit tests for the JWT validation logic, the Kafka producer/consumer paths, and the transaction ownership check would prevent regressions in the most security-critical code paths. Finance-agent LLM routing logic is a strong candidate for prompt-level evaluation.
Effort: High
Low — Developer Experience
Low
Add GITHUB_REPO_URL to .env for ArgoCD Application CR auto-wiring
The ArgoCD Application CR in deploy-local.sh references the GitHub repository URL. This value must be set as GITHUB_REPO_URL=https://github.com/jibolaolu/sre2026-final-project.git in the project .env for the ArgoCD sync to connect to the correct remote on a fresh deploy. Currently requires manual intervention.
Effort: Trivial
Low
Correct deploy-local.sh output — prints datadoghq.com but site is EU (.eu)
The final deployment summary in deploy-local.sh prints https://app.datadoghq.com as the Datadog URL. The DatadogAgent CR sets site: "datadoghq.eu". The deploy summary should print https://app.datadoghq.eu to avoid confusion when operators try to find logs after deploy.
Effort: Trivial
Low
Add Kafka consumer lag dashboards to Datadog
With the Kafka integration properly configured in Datadog, consumer group lag metrics for activity-consumer-group would provide visibility into event processing backpressure. A lag alert threshold would fire before the audit trail falls behind under load, allowing operators to scale activity-service replicas proactively.
Effort: Low
